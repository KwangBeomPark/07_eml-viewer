# EML Viewer 배포·설치 정비 2단계 검수

기준일: 2026-10-07. 소스 버전 0.1.16을 유지했으며 기존 공식 배포 파일·사용자 설정을 변경하지 않았습니다.

## 구현한 배포 흐름

- `build_installer.ps1` 기본값은 미서명 검수본입니다. `-SkipSign`은 호환 인자로 유지하며 `-Signed`와 함께 사용할 수 없습니다. 모든 빌드·컴파일 출력은 고유한 `build/release-staging/<id>` 아래에 있습니다. 직접 Inno 컴파일의 기본 출력도 `build/installer-preview`입니다.
- `sign_and_release.ps1`은 검수 소스의 clean commit, 전체 pytest 및 PowerShell 서명 회귀 성공, 빌드 전후 소스 지문 일치를 요구합니다. `-SkipBuild`는 출처 불명 재사용을 막기 위해 거부합니다. 실제 서명은 사용자의 활성 서명 세션과 명시한 인증서에 의존합니다.
- 번들 안의 모든 EXE를 먼저 서명·검증하고 설치 파일을 생성합니다. 설치 파일도 한 번 서명·검증한 후 호환 별칭으로 복사합니다. 압축한 내부 EXE와 설치 EXE를 다시 읽어 해시·지정 인증서·유효 서명·타임스탬프를 검증합니다.
- `release_artifacts.py`는 전체 ZIP 멤버·페이로드 해시, 두 설치 이름의 동일성, 체크섬, 버전·커밋·소스 지문·테스트·서명 근거를 검사합니다. CLI 승격 경로는 JSON의 서명 표시만 믿지 않고 `VerifySignatures.ps1`로 실제 Authenticode를 다시 검사합니다.
- 버전별 `App07_EmlViewer_v<version>-manifest.json` 및 `App07_EmlViewer_v<version>-SHA256SUMS.txt`를 추가합니다. 기존 `SHA256SUMS.txt`와 이전 버전 파일은 그대로 보존합니다.
- 같은 버전의 공식 파일이 하나라도 있으면 서명 전에 거부합니다. 승격은 임시 사본을 검증한 후 배타적 하드 링크로 새 이름만 추가하며, 실패 시 이번에 생성한 파일 중 원래 해시·파일 식별자·크기·수정 시간이 유지된 파일만 되돌립니다. 외부 변경·교체가 있으면 해당 파일을 보존하고 경로와 원래 실패 원인을 안내합니다. 실패한 새 버전과 원본 진단 스테이지는 구분됩니다. 전원 차단 시 여러 파일 전체의 원자적 반영을 보장하는 방식은 아니며 기존 파일을 덮어쓰지 않는 계약입니다.
- 다른 저장소의 서명 도구 참조와 인증서 누락 시 조용히 서명을 생략하는 fallback을 제거했습니다. 도구는 명시 인자·환경변수, PATH, 앱 로컬, Windows SDK 순으로 탐색합니다. 잘못 지정한 도구 경로는 실패합니다.
- CI는 pytest 후 격리된 미서명 검수본만 만듭니다. 로컬 스크립트와 CI 모두 GitHub 릴리즈를 게시하지 않습니다. 다음 버전의 실제 게시 절차는 별도 검증 대상입니다.

## 설치·업그레이드 계약

AppId, `UsePreviousAppDir=no`의 기존 설치 경로 정책, 실행 파일 이름과 파일 연결은 유지했습니다.
`AppMutex=EmlViewerMutex`도 유지하므로 실행 중이면 설치 시작 시 사용자에게 정상 종료를 안내하고 안전하게 차단합니다. 자동 종료를 완료했다고 보지 않습니다.
`CloseApplicationsFilter=EmlViewer.exe,App07_EmlViewer.exe`와 `RestartApplications=no`를 명시하여 자동으로 이전 실행 상태를 재시작하지 않도록 했습니다.
설치 후 실행은 새 `{app}\EmlViewer.exe`를 선택하며, 이전 실행 파일 전체를 먼저 제거하지 않습니다.
`UserSetting`은 배포 페이로드에서 제외하고 제거 시에도 보존합니다.

현재 설치 이름은 고정 EXE이므로 같은 이름을 교체하는 방식입니다. 과거 `App07_EmlViewer.exe` 별칭의 실제 설치 이력과 소유권이 입증되지 않아 임의 삭제는 추가하지 않았습니다.
실행 중 구버전·다중 창·종료 거부·사용자 지정 설치 위치·취소·설치 실패·제거 후 설정 보존은 실제 Windows 검수에서 확인해야 합니다.

## 검증 결과

- 전체 `pytest tests -q`: **152 passed, 36 subtests passed**. 신규 배포 회귀 **32개**가 포함됩니다.
- 신규 회귀는 동일 버전 충돌, 잘못된 커밋·소스 지문·dirty 상태, 미실행 테스트·서명 테스트, 별칭 차이, ZIP 내부 교체, 체크섬 변조, 설정 포함, 경로 탈출·junction, 복사·링크·최종 검증 실패 후 이전 파일 보존을 확인합니다. 새 destination의 외부 내용 변경 및 동일 바이트의 다른 파일 교체 뒤 실패할 때 삭제를 거부하는 회귀도 포함합니다. 가짜 JSON 서명 표시와 미서명 EXE를 실제 Windows 서명 검증으로 거부하는 검사도 통과했습니다.
- `Test-ReleaseSigning.ps1`: **8개** 서명·도구·경로 보호 assertion 통과. 유효/무효 서명 객체는 테스트용 모의 값이며 실제 서명 성공을 의미하지 않습니다.
- PowerShell 구문 검사 및 새 Python helper·회귀 파일의 Ruff 검사 통과.
- Inno Setup 6 fixture 컴파일 통과. `UserSetting/settings.json`이 fixture 페이로드에 포함되지 않음을 확인했습니다.
- 실제 PyInstaller→Inno 미서명 전체 빌드 통과. 공식 폴더 대신 고유한 스테이지에 검수 설치 파일을 생성했습니다. 생성된 설치 파일은 실행하지 않았습니다.
- 기존 공식 6개 파일의 SHA-256은 빌드 전후 동일했습니다.
